# fcan_internal

Внутренняя шина CAN FD прибора [auto_probe](https://github.com/gravitymir/auto_probe)
и узлы на ней.

Каждый модуль прибора получает собственный микроконтроллер и выходит в общую
шину одним четырёхжильным кабелем. Мозг прибора — плата на STM32H723 — перестаёт
быть распределительным щитом на двадцать проводов и становится одним узлом среди
прочих.

## Зачем

Сейчас модули «глупые»: трансивер или усилитель без собственной логики, от
каждого к контроллеру идёт свой пучок проводов. Это работает на столе, но имеет
три недостатка, и все три упираются в одно и то же — **плату-мозг приходится
переделывать всякий раз, когда добавляется модуль.**

Шина это развязывает. Добавление шестого узла не трогает ни один из пяти
существующих и не трогает плату-мозг. Любой узел можно перевыпустить на другом
микроконтроллере через два года — и он встанет в ту же гирлянду.

Цена решения честная: узел дороже глупого модуля примерно на **$3.5**, и
прошивок становится не одна, а по одной на узел.

## Стандарт шины

Главный документ проекта — **[docs/BUS.md](docs/BUS.md)**. Там зафиксировано
всё, что обязано совпадать у всех плат: разъём, распиновка, напряжение,
топология, скорость, план идентификаторов.

Коротко:

| | |
|---|---|
| Разъём | JST PH 2.0 боковой, `S4B-PH-K-S`, **две колодки** на узел |
| Распиновка | 1 `+5V`, 2 `CANH`, 3 `CANL`, 4 `GND` |
| Питание | 5 В в кабеле, LDO 3.3 В на каждом узле |
| Топология | линейная гирлянда, терминаторы 120 Ом только на концах |
| Протокол | CAN FD с BRS, **250 кбит/с арбитраж, 1 Мбит/с данные** |
| Контроллер узла | STM32G0B1CBT6, LQFP-48 |
| Трансивер | TCAN332G |

Скорость выбрана не случайно: она совпадает со встроенным в ПЗУ загрузчиком
STM32G0B1, у которого эти параметры зашиты намертво. Благодаря этому **прошивка
любого узла заливается по той же шине**, без программатора и без собственного
загрузчика.

## Ядро узла

Всё, что одинаково на каждом узле — STM32G0B1, кварц, TCAN332G, питание
5 → 3.3 В, две колодки, USB-C, кнопки, — заморожено как схемный блок:
**[docs/CORE.md](docs/CORE.md)**, в генераторе — [`lib/gen/core.py`](lib/gen/core.py).
Новый узел — это ядро плюс своя часть. Общие скрипты сборки и проверок всех
плат лежат в [`lib/gen/`](lib/gen).

## Узлы

| Узел | Состояние | Описание |
|---|---|---|
| [volt](nodes/volt) | проектируется | вольтметр ±43 В с распознаванием типа провода |
| can | план | шлюз в CAN автомобиля, **два** трансивера |
| lin | план | два канала LIN / K-line |

`voice_cell` на шину не заходит: у ESP32 контроллер TWAI понимает только
классический CAN и в FD-шине начнёт сыпать ошибками. Он остаётся на UART и
Wi-Fi — и это правильно, потоки звука шине управления не место.

## Состояние

Проект начат 17 ноября 2026. Сейчас зафиксирован стандарт шины и ведётся
проектирование первого узла — вольтметра.

Предыдущее поколение «глупых» модулей живёт в отдельных репозиториях
([can_probe](https://github.com/gravitymir/can_probe),
[volt_probe](https://github.com/gravitymir/volt_probe),
[lin_probe](https://github.com/gravitymir/lin_probe)) и остаётся рабочим.
Их схемотехника — основа узлов здесь.

Текущая стендовая распайка глупых модулей к H723 описана в
[auto_probe/docs/WIRING.md](https://github.com/gravitymir/auto_probe/blob/master/docs/WIRING.md).
